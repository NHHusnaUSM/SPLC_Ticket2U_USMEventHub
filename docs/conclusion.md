  Transitioning a software engineering team from informal, craft-based execution to disciplined lifecycle management requires aligning formal governance with agile
adaptability rather than imposing rigid bureaucracy. Through our comparative process audit of Ticket2U and the USM Event Management Hub, this report demonstrates
how targeted process engineering eliminates the root causes of concurrency bugs, requirement creep, and integration delays. Specifically modelling Code Review and
Static Analysis in a relational SPEM 2.0 Notion EPG alongside a zero-anti-pattern RACI Matrix establishes clear role accountability, while INVEST user stories and
Given-When-Then scenarios lock down ambiguous organizer requests before coding begins.

  Furthermore, pairing symmetrical V-Model testing gates with Lean waste remedies and Extreme Programming (XP) practices, such as Pair Programming, Test-Driven
Development, and Continuous Integration, ensures that high-risk payment webhooks and atomic seat-locking transactions are verified continuously rather than
debugged during last-minute releases. Finally, evaluating our project context through Munch’s 4 Ps and Tuckman’s team development stages confirms that a 
risk-tiered Scrum + V-Model hybrid, backed by transparent Fist-of-Five consensus governance provides the optimal balance of speed, code quality, and team ownership
for delivering reliable event-ticketing software.
